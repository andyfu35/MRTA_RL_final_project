# Experiment 2 Fixed-Horizon Fresh Shared-Joint PPO

## Why this revision exists

The first from-scratch Fresh Joint run still waited for complete episodes before updating. In the first 22 rounds it produced zero training successes and zero validation successes. It also frequently generated roughly 22k-24k finalized transitions and then selected only 8,192, so much of the supposedly fresh experience was discarded.

The corrected architecture follows the usual fixed-horizon PPO interaction loop instead of draining complete episodes.

## Training loop

Both policies start from fresh random Actor-Critic weights.

```
P_k
-> 64 shared worlds x exactly 128 simulator steps
-> finalize terminal fragments normally
-> bootstrap still-alive fragments with V(s_next)
-> PPO one epoch for R0
-> PPO one epoch for R1
-> synchronous commit P_(k+1)
-> immediately continue the worlds using P_(k+1)
```

The physical episode does not need to end at the PPO boundary. A world that is still active after step 128 continues from the same state during the next rollout, but all new actions are generated by the newly committed policy version.

## Fixed horizon

Formal settings:

- 64 shared joint worlds
- 128 simulator steps per rollout
- exactly 8,192 world transitions per round
- 100 rounds
- planned total: 819,200 world transitions
- PPO epochs: 1
- minibatch size: 256
- no target-KL guard

A Runner that dies stops producing actor samples until its team world resets. Therefore an individual policy can have fewer than 8,192 valid actor samples in a round. Those valid samples are all used; there is no random 8,192-of-23,000 transition subsampling anymore.

Expected diagnostics:

```
sim=8192
discard=0
joint=1
pv=<previous committed policy version>
dataep=1
stop=0
```

`samples` can be below 8,192 if that Runner died during some worlds.

## GAE at the PPO boundary

If a Runner is alive when the 128-step rollout ends, the fragment is not marked terminal.

The final temporal-difference residual uses:

```
delta_t = r_t + gamma * V(s_{t+1}) - V(s_t)
```

and GAE bootstraps from the stored next-state value.

Only a real environment terminal/death cuts value propagation.

This allows the policy to update every 128 steps without waiting for a 360-step timeout.

## Shared worlds

R0 and R1 act in the exact same 64 worlds and therefore observe the same:

- static map
- team episode
- teammate behavior
- success/failure event

Their Actor-Critic samples remain separate.

If a Runner collides, its policy fragment terminates on the collision transition and receives the collision reward. A later teammate success is not retroactively added to the already terminated dead Runner trajectory. This avoids keeping stale older-policy data across PPO boundaries and also removes the previous sacrificial `-100 + delayed +100` cancellation.

## Goal-related dense reward

The one-time terminal success bonus is deliberately unchanged:

```
team_success_bonus = +100
```

What changed is the dense reward for making progress toward the goal:

```
self_progress_scale: 3 -> 8
team_progress_scale: 2 -> 4
```

The alive-step reward is now:

```
r_i =
  8 * self_progress_i
+ 4 * team_progress
- 0.01
- 3 * danger_i^2
```

For example, when the Runner and team-best distance both improve by 0.10 m in one step, the goal-related dense reward is approximately:

```
8 * 0.10 + 4 * 0.10 = +1.20
```

Previously the same progress produced only:

```
3 * 0.10 + 2 * 0.10 = +0.50
```

The purpose is to make genuine movement toward the goal more attractive than merely learning to avoid collision and survive until timeout, without inflating the one-time terminal reward.

## Unchanged

- random initialization; no old checkpoint
- 20 x 20 environment
- 14 obstacle distribution
- 18-D observation
- learning rate 3e-4
- gamma 0.99
- GAE lambda 0.95
- PPO clip 0.2
- entropy coefficient 0.005
- safety scale 3
- collision penalty -100
- timeout penalty -20
- terminal success +100
- validation seeds 40000-40199

## Run

Do not resume the earlier incomplete Fresh Joint run because its collector and reward semantics are different.

```bash
git fetch origin

source .venv/bin/activate
pip install -e .
python -m pytest -q

mkdir -p runs/exp2_two_runner_fixed_horizon_scratch

python -m marl2d two-train \
  --config config/two_runner_fresh_joint.yaml \
  --from-scratch \
  --output runs/exp2_two_runner_fixed_horizon_scratch \
  --device cpu 2>&1 | tee runs/exp2_two_runner_fixed_horizon_scratch/train.log
```

The first sanity check is that every round prints `sim=8192` and `discard=0`. The research question is then whether stronger continuous goal progress produces successful trajectories from scratch without needing curriculum.
