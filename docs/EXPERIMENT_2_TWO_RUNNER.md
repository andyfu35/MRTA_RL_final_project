# Experiment 2: Two-Runner Cooperative PPO

## Goal

Experiment 2 trains two independent Runner policies before introducing Blockers. The team succeeds when either Runner reaches the goal. Both policies receive the shared team-success signal, while collisions remain individual safety costs.

## Agents and policies

- `runner_0` owns its own Actor-Critic PPO policy.
- `runner_1` owns its own Actor-Critic PPO policy.
- Parameters are not shared or averaged.
- At PPO round `k`, both workers collect from the same frozen policy set `{R0^k, R1^k}`.
- Both updates must be READY before the coordinator commits round `k+1`.

## Observation

Each Runner receives 18 values:

1. goal relative XY in body frame: 2
2. heading `sin(theta), cos(theta)`: 2
3. 8-ray lidar: 8
4. own collision flag: 1
5. previous left/right action: 2
6. teammate relative XY in body frame: 2
7. teammate alive flag: 1

The first 15 values preserve the Experiment 1 input order exactly.

## Warm start

Both Runner policies initialize from the finalized Experiment 1 Safe3 Round80 checkpoint:

`runs/exp1_r2_safe30_r70_to_r100/round_00080.pt`

The trained 15-input first-layer weights are copied into columns `0:15` of the new 18-input model. Columns `15:18` start at zero. All compatible hidden, actor, critic, and `log_std` parameters are copied. Adam state is not copied.

## Reward

For an alive Runner `i` before terminal events:

`r_i = 3*self_progress_i + 2*team_progress - 0.01 - 3*danger_i^2`

with safety distance `0.5 m`.

Terminal semantics:

- individual collision: that Runner gets `-100`, dies, and its future command is forced to `[0, 0]`
- teammate continues after an individual death
- either alive Runner reaches the goal: team success, shared `+100` team credit for both policies
- both dead: team failure and immediate episode end
- timeout: each Runner still alive receives `-20`
- precedence within one step: team goal > collision/death > timeout

A Runner that died earlier can still receive the shared `+100` episodic team-success credit if its teammate later reaches the goal. Its earlier `-100` collision cost remains separate.

## Dead-agent PPO samples

A dead Runner produces no actor samples after death. Its last valid trajectory remains pending until the team episode outcome is known. If the teammate later succeeds, the shared `+100` is added to the dead Runner's last valid transition before GAE/returns are finalized.

## On-policy round boundary

This section supersedes the earlier design text that allowed pending trajectories or surplus finalized samples to cross a PPO round boundary.

Each PPO update consumes exactly 8192 valid target-agent samples generated by one frozen policy version.

Collection works as follows:

1. collect complete team episodes under frozen round-`k` policies
2. once at least 8192 finalized valid target samples exist, stop launching new episodes
3. allow every episode already in progress to terminate naturally so delayed team credit becomes known
4. seal the round-`k` sample pool
5. consume exactly 8192 samples for PPO
6. discard same-round surplus samples rather than carrying them into round `k+1`
7. start fresh episodes only after the round-`k` pool is sealed

This preserves strict on-policy/frozen-version semantics. No unfinished episode is forcibly reset; instead, the worker drains in-flight episodes before the round ends.

Because full checkpoints are saved at committed round boundaries, pending trajectory and surplus queues are expected to be empty at normal checkpoint time. Environment instances, map/episode seed progression, model state, optimizer state, collector observations, and RNG-relevant deterministic round seeding remain resumable.

## Formal configuration

`config/two_runner.yaml`:

- samples per PPO update per Runner: 8192
- runner_0 parallel worlds: 32
- runner_1 parallel worlds: 16
- PPO hidden sizes: `[64, 64]`
- learning rate: `3e-4`
- gamma: `0.99`
- GAE lambda: `0.95`
- clip: `0.2`
- entropy coefficient: `0.005`

Data splits:

- validation: seeds `40000-40199`, every 5 rounds
- confirmation/evaluation: seeds `50000-50199`
- untouched final: seeds `60000-60199`

Best-checkpoint selection is safety constrained:

1. prefer checkpoints with `any_collision_rate <= 0.10`
2. among eligible checkpoints, maximize `team_success_rate`
3. break ties with lower `both_dead_rate`
4. then higher mean team reward

## Commands

Initial training from Experiment 1 Safe3 Round80:

```bash
python -m marl2d two-train \
  --config config/two_runner.yaml \
  --init-single-runner-checkpoint runs/exp1_r2_safe30_r70_to_r100/round_00080.pt \
  --rounds 100 \
  --output runs/exp2_two_runner \
  --device cpu
```

Resume:

```bash
python -m marl2d two-train \
  --config config/two_runner.yaml \
  --resume runs/exp2_two_runner/latest.pt \
  --rounds 50 \
  --output runs/exp2_two_runner \
  --device cpu
```

Validation/evaluation:

```bash
python -m marl2d two-eval \
  --checkpoint runs/exp2_two_runner/best.pt \
  --episodes 200 \
  --seed-start 40000 \
  --output runs/exp2_two_runner/eval_best_40000.json \
  --device cpu
```

Do not use seeds `60000-60199` until the final Experiment 2 checkpoint and selection rule are locked.

## Experimental status through 2026-09-18

Four formal Experiment 2 variants have now been run:

1. original 8,192-sample instantaneous-Euclidean baseline
2. 32,768-sample Large-Batch controlled ablation
3. 32,768-sample Record-Progress reward ablation
4. 32,768-sample Geodesic-Progress reward ablation

The complete experiment history, key checkpoints, aggregate results, supported/rejected hypotheses, and next recommended controlled test are maintained in:

`docs/EXPERIMENT_2_RESULTS.md`

Current headline results:

- Original baseline peak success: **61.0%**
- Large-Batch peak success: **67.5%**
- Record-Progress peak success: **61.0%**
- Geodesic-Progress peak success: **55.5%**
- Large Batch currently provides the strongest task-success result.
- Record-Progress reduces collision relative to Large Batch but sacrifices some success.
- Geodesic-Progress did not improve success despite `geo_fb=0.000`, so its distance field was active throughout the run.
